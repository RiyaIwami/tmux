# レビュー改善ルール

**プルリクエストのレビュー指摘事項を恒久的なガイドライン改善に活用するルール**

## 基本方針
- **すべてのレビュー指摘事項は再発防止のためにガイドラインに反映する**
- **指摘された問題は、個別修正だけでなく、ルールとして体系化する**
- **類似の問題を事前に防ぐための予防的ガイドライン更新を行う**

## レビューID管理システム

**レビューコメントとリプライの厳密な追跡システム**

### ログ記録フォーマット

#### 1. レビュー発見時（初回記録）
```
[YYYY-MM-DD HH:MM:SS] PR#{番号} [ReviewId:{ID}] {指摘内容} -> {必要な修正内容}
```

#### 2. 修正完了時（更新記録）  
```
[YYYY-MM-DD HH:MM:SS] PR#{番号} [ReviewId:{ID}][ReplyId:{ID}] {指摘内容} -> {実際の修正内容} -> ガイドライン遵守確認済み
```

### 実装手順

1. **レビュー発見時**
   ```bash
   # GitHub CLIでレビューID取得
   gh pr view {PR番号} --json reviews
   
   # レビューコメント取得（基本）
   gh api repos/{owner}/{repo}/pulls/{PR番号}/comments
   
   # レビューコメント取得（ページネーション対応）
   # 注意：30件を超えるレビューコメントがある場合は--paginateオプションが必須
   gh api repos/{owner}/{repo}/pulls/{PR番号}/comments --paginate
   
   # 元のレビューコメント数確認
   gh api repos/{owner}/{repo}/pulls/{PR番号}/comments --paginate --jq '.[] | select(.in_reply_to_id == null) | .id' | wc -l
   
   # 全ての元レビューコメントID取得
   gh api repos/{owner}/{repo}/pulls/{PR番号}/comments --paginate --jq '.[] | select(.in_reply_to_id == null) | .id'
   ```
   
   **重要**: GitHub APIは通常30件ずつしか返さないため、大量のレビューコメントがある場合は`--paginate`オプションを使用して全件取得すること

2. **修正作業実施**
   - 指摘事項の修正実装
   - 関連ガイドラインの更新
   - テスト実行・確認

3. **リプライ投稿**
   ```bash
   # レビューコメントへのリプライ投稿（ReplyIDが返される）
   gh api --method POST repos/{owner}/{repo}/pulls/{pr_number}/comments --field body="修正完了しました" --field in_reply_to={comment_id}
   ```

4. **ログ更新**
   - 同じレビューエントリにReplyIDを追加
   - 修正内容の詳細を記録

5. **コミット・プッシュ・プルリクエスト更新（必須）**
   ```bash
   # 修正内容をコミット
   git add .
   git commit -m "レビュー指摘事項の修正完了

   - 指摘事項1: 修正内容の詳細
   - 指摘事項2: 修正内容の詳細
   - 指摘事項3: 修正内容の詳細
   
   🤖 Generated with [Claude Code](https://claude.ai/code)
   
   Co-Authored-By: Claude <noreply@anthropic.com>"
   
   # リモートリポジトリにプッシュ
   git push origin {ブランチ名}
   ```
   
   **重要**: レビュー対応は修正実装だけでなく、必ずコミット・プッシュまでを含めて完了とする

### 管理上の利点

- **未対応レビューの特定**: ReplyIdがないエントリが未対応
- **対応状況の可視化**: 段階的なログ更新で進捗明確
- **レビュアーとの履歴追跡**: ID基準で正確な対応関係把握
- **複数レビューの並行管理**: ReviewId別に独立して追跡可能

## レビュー対応フロー

### 1. レビューコメント受信時
- 全てのレビューコメントを必ず確認し、見逃しなく対応する
- 各コメントに対して適切に返信する
- 指摘事項を分類し、どのガイドラインに反映すべきか判断する

### 2. 修正実装時
- 指摘された箇所の修正を行う
- **同様の問題が他の箇所にもないか全体を確認し、発見次第修正する**
- 修正内容をレビュアーに報告する

### 3. ガイドライン反映時（必須）
- 指摘事項を該当ガイドラインに新規ルールとして追加する
- 既存ルールと矛盾がないか確認し、必要に応じて既存ルールを更新する
- 反映したガイドライン変更をコミットに含める
- **全レビュー指摘事項から共通パターンを抽出し、再発防止ルールを追加すること**
- **ガイドライン更新後は必ずコミット・プッシュまで完了すること**
- **レビュー修正後は必ず該当レビューコメントスレッドに返信すること**

### 4. レビュー対応完了時（必須）
- **全ての修正内容をコミット**
- **feature/developブランチにプッシュ**
- **プルリクエストを更新**
- **レビュアーに対応完了を通知**

```bash
# 修正内容の確認
git status
git diff

# 全ての修正をステージング
git add .

# レビュー対応コミット
git commit -m "レビュー指摘事項の修正完了

主な修正内容：
- Laravel Breezeの使用停止とAuthController削除
- インポート文の改行・インデント統一
- バリデーション日本語化対応
- Bladeテンプレートのフォーマット統一
- マイグレーションファイルの改善
- Seederの実装

🤖 Generated with [Claude Code](https://claude.ai/code)

Co-Authored-By: Claude <noreply@anthropic.com>"

# リモートにプッシュ
git push origin feature/task-crud-implementation
```

## ガイドライン更新例

### Before（指摘前）
```markdown
- フォームにはバリデーションを実装すること
```

### After（指摘後）
```markdown
- フォームにはバリデーションを実装すること
- **ファイルアップロード時は必ずmimeTypeとサイズ制限のバリデーションを追加すること**
- **日時入力では過去日チェックとフォーマット検証を必須とすること**
```

## 継続的改善サイクル
1. **プルリクエスト作成** → 2. **レビュー受信** → 3. **修正実装** → 4. **ガイドライン反映** → 5. **次回実装での適用** → 1へ戻る

## レビュー記録の保持
- **レビュー指摘事項は`./._log/review_history.log`に必ず記録すること**
- レビュー指摘事項は該当ガイドライン内に「****」として直接記録する
- ガイドライン更新履歴はGitコミット履歴で追跡する

### レビューログ記録フォーマット
```
[YYYY-MM-DD HH:MM:SS] PR#番号 [指摘カテゴリ] レビュアー指摘内容 -> 修正内容 -> ガイドライン反映:[反映先ガイドライン名]
```

例：
```
[2025-07-11 15:35:01] PR#1 [コントローラー] メソッドチェーンが長すぎる -> 複数行に分割 -> ガイドライン反映:CONTROLLER_GUIDE.md
[2025-07-11 15:35:02] PR#1 [テスト] バリデーションテストが不足 -> 境界値テスト追加 -> ガイドライン反映:TEST_GUIDE.md
[2025-07-11 15:35:03] PR#1 [セキュリティ] XSS対策が不十分 -> エスケープ処理追加 -> ガイドライン反映:SECURITY_GUIDE.md
```

# レビュー指針

## Claude Code向けレビュー対応完全ガイド

### 1. レビュー受信時の基本フロー
1. **全レビューコメントを漏れなく取得**
   ```bash
   gh api repos/{owner}/{repo}/pulls/{pr_number}/comments
   ```
2. **各コメントIDを記録** (ReviewID管理システムに従う)
3. **修正実施前に返信** (対応予定を明記)
4. **修正実施** (該当ガイドライン参照・更新)
5. **修正完了後に返信** (具体的修正内容を明記)

### 2. 必須対応項目
- **ガイドライン準拠**: CODING_STANDARDS.md, CONTROLLER_GUIDE.md, MODEL_GUIDE.md, ROUTING_GUIDE.md, TEST_GUIDE.md, SECURITY_GUIDE.md, VIEW_GUIDE.md, TABLE_GUIDE.md
- **テスト網羅**: Happy Path / Unhappy Path 両方を必ず含む
- **命名規則**: 各ガイドラインで定義された命名規則を厳密遵守
- **責務分離**: 単一責任原則の徹底
- **型安全性**: declare(strict_types=1)とすべてのメソッドに型宣言

### 3. レビュー指摘の分類と対応方針

#### A. コーディング規約違反
- **対象**: CODING_STANDARDS.md違反
- **対応**: 即座修正 + ガイドライン確認・更新
- **例**: インポート順序、命名規則、NULLチェック方法

#### B. アーキテクチャ違反
- **対象**: 各種GUIDE.md違反
- **対応**: 設計から見直し + 該当ガイドライン更新
- **例**: コントローラー責務、ルーティング設計、モデル設計

#### C. セキュリティ違反
- **対象**: SECURITY_GUIDE.md違反
- **対応**: 最優先で修正 + セキュリティガイドライン強化
- **例**: バリデーション不備、認可処理抜け

#### D. テスト不足
- **対象**: TEST_GUIDE.md未遵守
- **対応**: 不足テストケース追加 + テスト設計見直し
- **例**: エッジケース不足、異常系テスト不足

### 4. レビュー対応時の必須作業
1. **指摘箇所の修正**
2. **同様箇所の一括修正** (プロジェクト全体を確認)
3. **該当ガイドラインの更新** (再発防止)
4. **テスト実行確認** (全テストパス確認)
5. **レビューヒストリログ更新** (review_history.log)

## レビューコメントへの対応

### 基本ルール
- **レビューコメントには必ず返信すること**
- 各レビューコメントに対しては`in_reply_to`パラメータを使用してReplyで対応すること
- 新しいコメントを作成するのではなく、元のコメントにReplyする形で返信すること
- 返信では修正予定の内容と対応方針を明確に記載すること
- レビュー指摘事項を修正した後は、修正完了の旨を返信すること

### 全レビューコメント確認方法
プルリクエストの全レビューコメントを確実に取得するには、以下のコマンドを使用する：

```bash
# 方法1: プルリクエストの全コメントを詳細取得（推奨）
gh api repos/{owner}/{repo}/pulls/{pr_number}/comments

# 方法2: 簡易レビュー一覧取得
gh pr view --json reviews

# 方法3: 複数コマンドで包括的に確認
gh pr view --json reviews && gh api repos/{owner}/{repo}/pulls/{pr_number}/comments
```

### 見逃し防止のための確認手順
1. **gh api repos/{owner}/{repo}/pulls/{pr_number}/comments** で全コメントを取得
2. 各コメントの`id`フィールドを確認
3. 返信済みでないコメントIDに対して返信を実施
4. 修正が必要な場合は、修正後に修正完了の旨を返信

### Claude Code専用返信ルール
**Claude Codeが返信する際は、必ず返信内容の先頭に【Claude Codeが返信】を付けること**

- 自分の返信とユーザーコメントを判別するため
- 重複返信の防止のため
- レビュー履歴の追跡を容易にするため

### レビューコメント返信例
```bash
# Claude Code専用返信フォーマット
gh api repos/{owner}/{repo}/pulls/{pr_number}/comments -X POST \
  --field body="【Claude Codeが返信】承知しました。指摘事項を修正します。" \
  --field in_reply_to={comment_id}

# 修正完了時の返信例
gh api repos/{owner}/{repo}/pulls/{pr_number}/comments -X POST \
  --field body="【Claude Codeが返信】修正完了しました。TaskControllerのメソッドチェーンを1つの連続したチェーンに統合しました。" \
  --field in_reply_to={comment_id}
```

## 品質保証

### レビュー修正時の必須チェック
- **レビュー修正時は必ず`./docs/REVIEW_GUIDE.md`のレビュー指針を確認・遵守すること**
- レビュー修正では、修正箇所と同様の箇所を見つけた場合、指示されていなくても修正すること
- また、指摘箇所をClaudeが読み込みやすい形でガイドラインを更新し反映するように
- **レビュー指摘事項は必ず該当ガイドラインに反映すること（レビュー改善ルール）**
