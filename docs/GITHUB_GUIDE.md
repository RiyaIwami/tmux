# GitHub 運用ガイド

このドキュメントは、LaravelプロジェクトにおけるGitHubの活用ルールを定義します。

---

## ブランチ戦略

### 基本方針

```text
main       -> リリース用
develop/*    -> 粒度の大きい機能追加の場合の統合ブランチ
feature/*  -> 機能ごとの開発用
fix/*      -> 不具合修正用
```

### 命名規則
- ブランチ名はケバブケース
- 新機能：feature/機能名-詳細-識別子
  * 例：feature/user-registration-form
- 粒度の大きい新機能：develop/機能名
  * 例：develop/add-saas-system
- 修正対応：fix/不具合-内容-識別子
  * 例：fix/login-redirect-bug

### ブランチ作成

- **機能追加時には必ず新規ブランチを作成**
- 作成元は明示的に `develop` または適切な派生ブランチから分岐
- 作成コマンド：
    ```bash
    git checkout -b feature/{内容}
    ```

## コミットルール
- コミットは細かく・明快に・理由がわかるように記述
- メッセージは基本「日本語」で統一（例：タスク作成機能を実装）
- 複数の修正を1コミットにまとめず、機能・修正単位で細分化

## プルリクエストルール
- ```git push origin {ブランチ名}```ででプルリクエストを作成
- プルリクエストの名前は実装内容に準拠し、分かりやすく簡潔に日本語で記述
  * ユーザー登録機能の追加

## プルリクエスト作成時チェックリスト
- 全ての`.claude/`ディレクトリ内の各mdファイルの要件を満たしているかを確認
- **必ずテストコード全てを動かし、エラーが出ないことを確認すること。全てのテストケースが通過するまで修正を行い続けること。**
- mdファイルに更新があった場合、最新を読み込み自分のブランチにマージ。そしてその更新分の実装も行うこと。
- 自身のコードに対しても セルフレビューを実施

## 禁止事項
- mainブランチに直接pushしてはいけない。
- mainブランチにマージの操作を行なってはいけない。
- 作成したブランチを許可なくクローズしてはいけない。
